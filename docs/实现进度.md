本文记录当前代码实现了什么、与开发文档哪里不一致、以及下一步按什么顺序补齐。**当前代码未经独立安全审查，不能对外宣称“安全聊天”或“零知识”**（见开发文档 1.3）。

## 1. 已实现

| 模块 | 内容 | 测试 |
|---|---|---|
| IP 准入 | 白名单（IPv4 精确、IPv6 按 /64）、访问密码（Argon2id）、邀请链接/邀请码放行、管理员审批、5 次失败封 1 小时 / 累计 20 次永久封、闲置 90 天自动失效、只信任反向代理的 X-Forwarded-For、未授权 IP 只能看到独立验证页 | 接口 + 浏览器 |
| 认证（OPAQUE） | 用 `@serenity-kit/opaque`（基于 Rust `opaque-ke`，已有第三方安全审计报告）。注册、登录、改密码（用旧密码重新认证）都走 OPAQUE，**服务器永远拿不到密码或密码等价物**。登录状态只存内存、一次性、2 分钟过期，重放的证明会被拒绝；不存在的用户名返回同样格式的响应。服务器 OPAQUE 公钥在浏览器端首次使用时固定，之后变化则拒绝登录。每次登录尝试（不只是失败）都计入限流：按用户名 10 次/小时、按 IP 30 次/小时 | 接口：重放拒绝、枚举一致、改密码踢下线 |
| 恢复词 | 注册时生成 24 个 BIP-39 英文词（256 位熵，带校验），手抄后需核对其中 3 个才能完成注册。恢复词作为**第二个 OPAQUE 账户凭据**注册，服务器不保存明文，也不保存可离线穷举的哈希。找回流程：恢复词 OPAQUE 认证 → 取回用恢复密钥加密的私钥备份 → 设置新密码 → **所有旧会话失效** | 接口 + 浏览器 |
| 私钥备份 | 身份私钥分别用「密码 OPAQUE 导出密钥」和「恢复词 OPAQUE 导出密钥」派生的密钥加密，存两份。只拿到数据库的人无法离线穷举（需要服务器的 OPRF 密钥参与） | 接口 |
| E2EE | Ed25519 + X25519 身份密钥；本地私钥用不可导出的 WebCrypto 密钥包装存 IndexedDB；按纪元的聊天密钥，密封给每个成员；**密封包签名覆盖 chatId、纪元、成员版本、收件人、分发者**；消息 XChaCha20-Poly1305 + 发送者签名 + 256 字节填充；带长度前缀的二进制 AAD（含协议版本）；128 位 clientMsgId，服务器唯一约束；安全码；TOFU，对方密钥变化时警告并禁止发送 | 接口：数据库无明文、篡改检出 |
| 签名的成员变更 | 建群/私聊、加人、踢人、退出、设管理员都是**成员自己签名的记录**，形成从创建开始的链。客户端逐条重放验证（版本连续、签名有效、操作者当时有权限），只向验证过的成员列表分发密钥；服务器给出的成员列表与签名链不一致时，界面显示红色警告并**停止发送和分发密钥**。加人/踢人与密钥轮换在同一个请求里原子完成；退出者不参与下一次轮换（由剩余成员完成，轮换完成前拒收新消息）；密钥包只接受「分发者在该成员版本中确实是成员」的 | 接口：伪造签名拒绝、非管理员越权拒绝、模拟恶意服务器偷加成员被检测 |
| 群邀请 | 邀请链接/短码/二维码。点链接只会**排队一个入群申请**，由在线管理员的客户端签名入群并轮换密钥（默认自动；可设为需要审批，管理员在群信息里批准/拒绝）。新成员看不到加入前的消息 | 接口 + 浏览器 |
| 聊天 | 私聊、群聊（≤50 人，群主/管理员/成员）、回复、编辑、已读回执、正在输入、在线状态、阅后即焚、群名加密 | 浏览器 |
| 加密附件（M6） | 图片、视频、音频、任意文件（≤100 MB）、语音消息（浏览器录音，Opus）。文件在浏览器里用 XChaCha20-Poly1305 secretstream 按 64 KiB 分块加密后上传，**文件名、类型、缩略图、文件密钥都在加密消息里**，服务器只看到一串字节和大小。任何分块被改动、调换顺序或截断都会解密失败。上传绑定到具体聊天，只有该聊天成员能下载，发出前只有上传者能下载；24 小时内没被消息引用的上传自动清理；消息被删除时附件文件一并物理删除。照片默认在本机重新编码，**去除 EXIF（拍摄位置、设备型号）**，可选“按原文件发送”。支持粘贴、拖拽、多文件、说明文字、上传进度、失败重试、图片大图查看、视频播放 | 接口：非成员/未发送不可下载、分块篡改与截断检出、磁盘无明文、删除后文件消失、未引用清理；浏览器：图片+文件+语音收发、下载内容与原文一致 |
| 消息能力（M4） | **转发**（用目标聊天的密钥重新加密；附件重新上传到目标聊天，文件密钥不变）、**表情回应**（emoji 用聊天密钥加密并签名后存服务器，每人每条一个）、**置顶**（私聊双方、群管理员；顶部置顶栏可点击跳转）、**@提及**（群里输入 @ 弹出成员；被提及方的聊天列表显示 @ 标记——提及信息在密文里，由客户端计算）、**安全的 Markdown**（粗体、斜体、删除线、行内代码、代码块、剧透，渲染为 React 节点，不输出 HTML；列表预览中剧透内容被遮住）、多选转发 | 接口：回应加密/签名校验、置顶权限；浏览器：回应、置顶、Markdown、@提及、转发图片进群 |
| 本地搜索（M7） | 聊天名 + **消息全文搜索**（含附件文件名和说明；中文按子串匹配，不需要分词）。解密后的消息存在本机 IndexedDB 的**加密缓存**里（与身份私钥同一把不可导出的 WebCrypto 密钥），后台逐页补齐历史（每个聊天最多 5000 条）。点击结果会打开聊天、自动向上加载并定位到那条消息。**删除同步**：为所有人删除、阅后即焚、仅为我删除、清空记录都会从本机缓存移除——在线时实时，重新打开时通过 `/api/sync/removed` 补齐离线期间的删除。可在设置里关闭并清除缓存；退出登录时清空 | 接口：删除同步只返回自己可见的删除；浏览器：搜索命中并跳转、IndexedDB 中无明文、删除后搜不到 |
| 离线只读 + PWA（M7） | Service Worker 缓存应用外壳（导航请求**网络优先**：服务器仍决定是否显示验证页，缓存只在断网时兜底）。断网打开时进入「离线模式」：从本机加密缓存显示聊天列表和消息，只能看不能发；网络恢复后自动刷新。manifest + 图标，可「添加到主屏幕」以独立窗口运行 | 浏览器：断网后刷新进入离线模式并能看到消息，恢复网络后自动回到在线 |
| 推送通知（M7） | Web Push（VAPID，密钥自动生成或读环境变量）。**推送内容固定为 `{"t":"msg"}`**：不含聊天、发送者或内容，推送服务商只能知道“有东西到了”。只推给没有在线连接的成员，每人 20 秒内最多一条；失效的订阅自动删除；订阅绑定登录会话，退出/被踢下线即失效。网页开着但在后台时，由浏览器本地生成通知，显示内容可选：不显示 / 仅发送者 / 发送者和内容 | 接口：只推离线成员、内容为空、节流、410 清理、会话删除级联 |
| 恢复词重新生成 | 设置 → 安全：输入当前密码（OPAQUE 重新认证）→ 生成新的 24 个词 → 旧恢复词立即失效 | 接口 + 浏览器 |
| 删除 | 仅为我删除、为双方删除（私聊中可删对方消息，不限时间）、清空我这边/双方、删除聊天、解散群、墓碑记录 | 接口 + 浏览器 |
| 管理后台 | 准入申请审批、白名单、封禁解除、验证日志、注册邀请、用户管理、访问密码、紧急锁定 | 浏览器 |
| 加固 | 严格 CSP（无第三方资源）、HSTS、同源校验、日志不记录 Cookie；OPAQUE 服务器密钥与已有账号不匹配时拒绝启动 | 接口 |

## 2. 与规范仍有差距

| # | 规范要求 | 当前实现 | 计划 |
|---|---|---|---|
| 1 | 5.2 `encKey = HKDF(Argon2id(password, userKdfSalt))` | 改用 OPAQUE 的 exportKey 派生备份密钥（见第 3 节理由） | ✅ 已确认采用（2026-09-28），开发文档 5.2 以此为准 |
| 2 | 6.3 邀请入群“由触发变更的管理员客户端轮换” | 已符合。例外：有人退出后由任一剩余成员轮换（退出者不能参与） | 若要求只由管理员轮换，可加限制 |
| 3 | 6.1 客户端保留已处理 clientMsgId 窗口 | 服务器强制唯一；客户端按 发送者+clientMsgId 去重；本机缓存按消息 ID 去重 | 已基本满足 |
| 4 | 成员签名链里的「角色变更」 | 已签名；但群名、阅后即焚设置仍只由服务器按角色校验，不签名 | 低风险，后续可纳入签名记录 |
| 6 | 7.2 贴纸/GIF、投票、定时发送、链接预览 | 未实现（均为 P2） | 后续 |
| 7 | 6.5 附件上传令牌（短期、绑定大小） | 用会话 Cookie + 聊天成员校验 + 每日 1 GB 配额代替；单文件 100 MB（文档写 200 MB，浏览器内存中整体加密，100 MB 更稳） | 若需要更大文件，改为流式分块加密上传 |
| 8 | 附件元数据 | 服务器能看到“某条消息带了几个附件、各多大”（为了鉴权下载和删除时清理文件） | 可接受；已在文档 1.3“不保护的内容”范围内 |
| 9 | 本机缓存与离线模式的边界 | 能打开这个浏览器配置文件的人，本来就能拿到身份私钥；缓存加密只防“直接拷走磁盘文件”。离线模式不经过 IP 验证（数据本来就在本机） | 公用电脑务必退出登录（会清空缓存）；或在设置里关闭缓存 |
| 9b | 推送元数据 | 推送服务商（Google/Mozilla/Apple）能看到推送发生的时间和目标设备 | 可在设置里不开启推送 |
| 10 | 7.6 音视频通话（WebRTC + coturn） | 未实现（P2） | M9 |
| 11 | M8 独立安全审查、备份恢复演练 | 备份恢复：✅ v0.2.0 每日自动备份 + 恢复演练脚本（已在生产服务器演练通过）。独立安全审查：未做 | 安全审查上线前必须完成 |

## 3. 实现选择与理由

| 项目 | 选择 | 原因 |
|---|---|---|
| 备份密钥来源 | OPAQUE exportKey → BLAKE2b 派生 | exportKey 只有知道密码且完成 OPAQUE 的客户端才能得到。用 Argon2id(password, 公开盐) 派生时，拿到数据库的人可以离线穷举密码解开备份；用 exportKey 则每猜一次都必须与服务器交互，受限流约束 |
| 恢复词验证 | 第二个 OPAQUE 记录 | 不向服务器发送任何固定凭据，恢复词同样享受 OPAQUE 的抗离线攻击和防重放 |
| OPAQUE 参数 | 库默认 “memory-constrained” Argon2id（64 MiB，3 次迭代） | 浏览器里 1 秒左右；在 Web Worker 中运行不卡界面 |
| OPAQUE 服务器密钥 | 优先读环境变量 `OPAQUE_SERVER_SETUP`，否则生成后存数据库 | 放环境变量可避免它随数据库备份泄露；换密钥会让所有账号失效，所以启动时校验 |
| ORM | better-sqlite3 + 手写迁移 | 表结构简单 |
| 发消息/编辑/删除 | REST；WebSocket 只推送事件 | 请求-响应语义清楚，便于测试 |
| 聊天 ID | 客户端生成 | 首条成员签名记录和首个密钥包要绑定聊天 ID |

## v0.3.0 功能（2026-09-29）

- **通话**：一对一 WebRTC 语音 / 视频。
  - 信令用聊天密钥加密，并用身份密钥签名（`sc-call` AAD，拒绝 2 分钟以前的消息），由 Socket.IO 转发。服务器只检查双方是否同在一个私聊。
  - TURN 使用 coturn REST 临时凭证，由 `ops/install-coturn.sh` 安装，脚本会禁止中转到内网地址。
  - 设置里有「只走中转」选项，可以隐藏自己的 IP。
  - 由主叫方发布加密的通话记录（`t:'call'`）。
- **投票**：`t:'poll'` 消息。每个人的选择单独加密、单独签名（`poll_votes` 表，`sc-vote` AAD）。结束投票的做法是由发起人签名编辑，把消息改成 `closed`。
- **定时消息**：`scheduled_messages` 表存放已加密的消息，由每 5 秒的定时器投递。如果期间密钥纪元变了，就标记为 stale，由发送方客户端重新加密后再 PUT（clientMsgId 不变，所以去重依然有效）。
- **草稿同步**：`drafts` 表。加密密钥由 `generichash('sc-draft-key' ‖ boxSk)` 派生，只有自己的设备能解开。
- **离线发件箱**：没有附件的消息先用本机不可导出的 AES-GCM 密钥加密存在 IndexedDB，联网后按顺序发出，服务器按 clientMsgId 去重。
- **合并转发**：`t:'bundle'` 消息，最多 100 条、10 个附件。附件以密文形式复制到目标聊天（`transferBlob`，大文件按范围分片复制）。
- **链接预览**：发送方自愿开启，由服务器代为抓取，抓取结果放进加密消息。
  - 防 SSRF：自定义 DNS lookup，所有解析结果都必须是公网地址，并直接连接校验过的 IP；每一跳重定向都重新校验；只允许 80 和 443 端口；限制大小和超时。
  - 图片在客户端重新编码成 JPEG 缩略图。
  - 管理员可以关闭（`limits.linkPreview`）。
- **大文件**：用 `uploads` 表实现断点续传：8 MB 分片、校验 offset、同一时间只处理一个分片。`GET /api/blobs/:id` 支持 Range。
  - 客户端用 secretstream 流式加密和解密，格式与原来一致。
  - 下载时优先用 File System Access API 直接写盘，不支持时退回 Blob。
- **签名群设置**：`titleCt` 里存 `{s:1, r, sig}`，由管理员对群名、阅后即焚时长和版本号 `v` 签名。
  - 客户端对照成员签名链校验签名者是否为管理员；本机记录见过的最高 `v` 以防回退；再与服务器实际执行的阅后即焚时长比对。
  - 密钥轮换时由任意成员原样转封，签名不变。
- **英文界面**：`lib/i18n.ts`，以中文原文作为 key，`i18n.en.ts` 里有 600 条英文。
- 数据库迁移 v6–v8 都是新增表，旧数据不动。

## v0.4.0 功能（2026-09-29）

- **联系人、拉黑、隐私**（`social.ts`，迁移 v10）：
  - 备注名、备注和已验证的身份公钥存在个人加密库 `user_vault`。密钥是 `generichash('sc-vault-key|' ‖ boxSk)`，只有自己的设备能解开。
  - `blocks` 表：拉黑后发消息、编辑、回应、投票、通话信令、输入状态都会被拦截；在线状态和已读回执双向隐藏。
  - `users.privacy`：在线状态和已读回执是否可见，规则是对等的。只有共享聊天的人才能看到在线状态。
- **收藏、贴纸**：同样放在个人加密库（kind 分别为 saved、sticker），附件属于 `self:<uid>`，个人空间上限 2 GB；重新 PUT 时，不再被引用的附件会被释放。
- **两步验证**（`totp.ts`，迁移 v11）：
  - RFC 6238，按时间步防重放；10 个一次性恢复码（哈希存储）。
  - 登录和找回时先返回 `{totpRequired, ticket}`，通过 `/api/auth/2fa` 后才下发会话和加密密钥。验证按账号和 IP 限流。
  - `limits.require2fa`：只允许 `enforce2fa` 白名单里的路径；Socket 连接也会被拒。
  - root 可用 `ops/reset-2fa.sh` 关闭某个账号的两步验证，网页后台没有这个功能。
- **扫码登录**（`link.ts`）：
  - 新设备生成临时 box 密钥对，旧设备扫码后用 `crypto_box_seal` 把密钥封给它。
  - 两边核对 6 位 linkCode。限制：每个 IP 每 10 分钟最多发起 10 次，每个账号每小时最多批准 5 次，全局最多 5000 条待处理。
  - 扫码用 BarcodeDetector，不支持时退回 jsQR。
- **群管理**（迁移 v12、v13）：
  - `chats.post_policy`（仅管理员可发言）、`chat_members.muted_until`，由 `assertCanPost` 统一检查。
  - 群公告 `ann` 放在签名群设置里。
  - 定期换钥：`rotateSoon`，当前密钥纪元超过 7 天或 1000 条消息时，由在线管理员客户端轮换。
- **导出**（`exporter.ts`）：
  - HTML 导出带 CSP，附件只内嵌 SAFE_MIME 白名单里的类型。
  - `.scarchive` 用 Argon2id（ops 3、128 MiB，参数写在文件头并做范围校验）加 secretstream。
  - 单个附件最大 25 MB，总计最大 150 MB。
- **管理后台**（`insights.ts`，迁移 v14）：
  - `admin_audit` 记录操作，敏感字段自动隐去；`daily_activity` 按天统计。
  - 附件保留天数到期后由 `purgeOldAttachments` 删除（跳过 `self:` 下的附件）。
  - `UPDATE_FEED_URL` 用于检查更新。
- **运维**：`ops/offsite.sh` 和 `ops/setup-offsite.sh` 用 gpg AES256（带 MDC）加 rclone 做异地备份；AccessKey 由用户自己在 `rclone config` 里输入。
- **体验**：图片查看器可缩放、拖动、切换同一聊天的图片；语音可倍速播放；手机上右滑回复；隐私屏。

  - challenge 只能用一次，并绑定到登录 ticket 或用户。
  - rpID 默认取 Origin，设置了 `PUBLIC_ORIGIN` 就固定用它。
  - 已经有第二步验证时，增删验证方式都要先用现有方式确认（`guardedProof`，按会话限流）。

  - 异地备份失败或长时间没上传会告警。

## v0.9.0 功能（2026-09-30）

- **私密通话**（`lib/call.ts`）：
  - 发起方调用 `startSecretCall`：生成 32 字节随机信令密钥，和 SDP offer 一起放进 inner `call` 消息（带 `at`），经双棘轮发给绑定设备。

  - 之后的 answer、ICE、挂断走原来的 `call:signal` 中转：路由用两人的私聊，epoch 为 0，用这把信令密钥加密，账号密钥签名。`onSignal` 看到 epoch 0 就逐个尝试已登记的信令密钥；epoch 0 上的 offer 一律拒收。
  - 通话记录由 `secretHooks.log` 写成本机的事件消息，双方各记一条。
- **私密对话补全**：
  - 新状态 `peer_gone`：发送时收到 `device_gone`，或打开对话时 `GET /api/secret/devices/:id?user=` 查询（只对聊天伙伴开放，被屏蔽者返回 403）确认设备已不存在，就进入这个状态。
  - 本机字段 `verified` / `pinned` / `muted`；侧栏里置顶的排在前面。
- **发布签名**：
  - `ops/verify-release.mjs`：Ed25519，使用 Node 自带的 crypto。更新包签名覆盖整个 tar.gz 文件。网页签名的内容是 `securechat-web-code|版本|指纹`，写在 `code-fingerprint.json.sig` 里。
  - `tools/release.mjs`（开发机用，不随包发布）：组装更新包，签网页清单，再签更新包。
  - `update.sh`：
    - 从网站目录启动时，改用 ROOT_OPS 里的脚本；
    - 把更新包和 `.sig` 用 `install -m 600` 复制进私有目录，只处理这份副本；
    - 没有固定公钥或签名不对时停止（可用 `ALLOW_UNSIGNED` 跳过）；
    - 已安装版本从 `$ROOT_OPS/installed-version` 读，比它旧的包不装（可用 `ALLOW_DOWNGRADE` 跳过）；
    - 回滚时 ROOT_OPS 也一起回滚。
  - `install-release-key.sh`：比对密钥 ID 后才固定公钥，已有公钥时必须加 `--replace` 才替换。`install_root_ops` 不再安装公钥。
  - 网页端用 `__RELEASE_PUBKEY__` 验证清单签名，并显示密钥 ID（SPKI 的 SHA-256）。
- **元数据**：
  - `padme()` / `padAttachment` / `unpadAttachment`：只补齐走内存的小文件（≤ 90 MB），读的时候按 payload 里的 `size` 截回原长。
  - `presence.ts`：
    - `coarseOnline`：显示在线延迟 1–5 分钟，显示离线延迟 20–40 分钟，广播里不带时间戳；
    - 用户改隐私设置时调用 `privacyChanged`，立即结算当前显示的状态。
  - `push.ts`：`pushDelay` 打开时，每个用户同一时间只挂一个 2–8 分钟后发出的推送。
- **群上限** `MAX_GROUP = 100`（邀请链接里的上限也一起改了）。
- **单条限时**：
  - 发消息时可以带 `ttl`（30 秒到 7 天），服务器取它和聊天自身阅后即焚时长中较短的一个。
  - 客户端 `setNextMessageTtl` 只作用于下一条；这个 ttl 会存进离线发送队列（outbox）和重试逻辑，选了限时后不能再定时发送。
- **续传不重选**：
  - `showOpenFilePicker`，或拖放时的 `getAsFileSystemHandle`，拿到文件句柄后，按 `resume-h:<uid>:<uploadId>` 存进 IndexedDB。
  - 续传提示条里的「继续上传」会先申请读取权限，再调用 `resumeFileSend`。
  - 句柄在上传完成、失效或退出登录时删除。
- **测试**：
  - 服务器 61 项，新增隐私延迟、单条限时、100 人上限，以及设备在线查询的权限。
  - 浏览器端到端测试新增：私密通话（只有绑定设备响铃）、已验证 / 置顶、单条限时、网页清单签名。
  - 100 人压力测试。
  - `update.sh` 模拟测试：签名错误、缺少签名、降级、未固定公钥，都会被拒绝。

## v1.0.0 运维（2026-09-30）

- `ops/doctor.sh`（新）：服务器自检，缺什么装什么。
  - 阶段：`pre`（工具、磁盘、Node.js）、`post`（依赖、`.env`/data 权限与 `HOST`、systemd 单元、ROOT_OPS、可选组件、日志上限）、`final`（服务、端口、健康检查）。不带 `--phase` 时全部运行，配置有变化会先重启。
  - `--check` 只检查；退出码 0 = 没有 ✘。参数不认识时报错退出（2）。
  - 包管理器：apt / dnf / yum（`iproute2`→`iproute`、`gnupg`→`gnupg2`）。
  - Node.js：`SHASUMS256.txt` 只从 nodejs.org 取；安装包先试 nodejs.org，再试 npmmirror，`sha256sum -c` 通过才用；装到 `/usr/local/lib/securechat-node`（root:root，go-w），旧的改名为 `.old-<时间>`。
  - 依赖检查以 `www` 身份运行：每个 `dependencies` 都能 `require.resolve`，better-sqlite3 能打开内存数据库。
  - 从网站目录启动时改用 ROOT_OPS 里的副本（`update.sh` 的私有副本除外）。
- `ops/common.sh`：
  - `root_safe`/`node_dir_ok`：Node 可执行文件、`npm` 和所有上级目录都必须属于 root 且没有 group/other 写权限，路径只能含 `[A-Za-z0-9._/+-]`；`find_node_bin` 依次试 `NODE_BIN_OVERRIDE`、宝塔 v22（从新到旧）、`OWN_NODE`、PATH。
  - `as_app`：`runuser -u www -- env -i PATH HOME=$APP_DIR LANG`（只额外传代理和 CA 变量）。
  - `app_npm_ci`：以 `www` 身份 `npm ci`，临时的 cache/HOME/devdir，`--userconfig /dev/null`，registry 取 root 的设置；有本机头文件时设 `npm_config_nodedir`。日志在 `/var/log/securechat/`。
  - `app_version`：`package.json` 以 `www` 身份读出后按 JSON 解析。
  - `backup_env`：见 CHANGELOG。
  - `write_units`：三个 systemd 单元只在内容变化时重写（`install-service.sh` 和 `doctor.sh` 共用），备份单元也带上 `PATH`。
  - `install_root_ops` 跳过符号链接。
- `ops/update.sh`：第 0 步 `doctor --phase pre`；`install_from` 以 `www` 身份 `rsync -rlptD`（包文件先 `chmod a+rX`，解包用 `--no-same-owner`）；安装后 `doctor --phase post`，失败即回滚；成功后 `doctor --phase final`（只提醒）。回滚时 ROOT_OPS 从升级前的副本恢复。trap 在自检之前设置。
- 其他脚本：`backup.sh`（版本号、`.env` 备份）、`restore-drill.sh`（`node --env-file`）、`reset-2fa.sh`、`install-coturn.sh`、`offsite.sh` 都不再以 root 执行或读写网站目录里的内容。
- 服务器：`HOST` 为空时按 127.0.0.1 处理（`||` 代替 `??`）。
- 首次从 v0.9 升级到 v1.0 时，运行的是服务器上 v0.9 的 `update.sh`（不含自检），升级后需要手动运行一次 `doctor.sh`。
- 二次审查后的补充：回滚时 `SAVED` 以 `www` 身份解到 `$RB/x`（`$RB` 为 root 的 711 目录）；`STG` 解包后 `chmod -R a+rX,ug-s`；`as_app` 在支持时用 `setsid -w`（防 TIOCSTI）；`NODE_BIN` 为空时 `node`/`npm` 被定义成报错函数；`node_dir_ok` 检查整个 Node 安装目录（`find -perm /022 -o ! -user root`）；`NEW_LOCK` 取自签名包；ROOT_OPS 快照失败即中止；降级到 v1.0 以前的包时跳过自检。
